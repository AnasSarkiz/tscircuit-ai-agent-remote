# C5656610 / ICS-43434 acoustic opening below the manufacturer recommendation

Investigated on 2026-10-03 using an unchanged live EasyEDA component response,
released `easyeda@0.0.368`, and `tscircuit@0.0.2736` for the generated board.
This investigation used the converter's public fetch/conversion APIs; it did
not independently execute CLI 0.1.2232. The hole matches the reported CLI output.

## Result

The discrepancy originates in the supplier-owned EasyEDA footprint, not in
hole conversion. The current import fails microphone qualification.

| Stage | Acoustic opening diameter |
| --- | --- |
| Raw EasyEDA footprint | 0.3999992 mm |
| Converter Circuit JSON | 0.39999919999999994 mm |
| Imported TSX | 0.3999992 mm |
| Circuit JSON generated by tscircuit 0.0.2736 | 0.3999992 mm |
| TDK recommendation, DS-000069 v1.2 page 17 | At least 0.50 mm |
| User's proposed correction target | 0.60 mm |

The unchanged source record is:

```text
HOLE~4007.0485~2992.0275~0.7874~gge363~0
```

The fourth field is radius in 10 mil units. Therefore
`0.7874 × 0.254 mm × 2 = 0.3999992 mm`. The converter's `handleHole`
performs precisely this calculation. The TSX generator emits that diameter
directly. The rendered hole remains at `(0.7650734 mm, 0 mm)`.

The footprint belongs to `lcsc` and is marked `writable: false` in the fetched
component response. Footprint UUID: `9a1bd085c9154f9fa0392ad1d3d15d6d`.
Symbol UUID: `bb5ae0d2bf12487ea3dcd0a34e5b28ca`.
The direct standalone footprint request was rejected with HTTP 403, so its
separate current revision could not be verified. The live component response
used by the official importer does contain the undersized hole.

## Corrective action

The LCSC/EasyEDA library owner must correct the acoustic drill diameter to
0.60 mm while retaining its center and all other source records. In the
EasyEDA source units, the target radius is `0.60 / (2 × 0.254)` =
`1.1811023622047244`. This is a correction specification for the owner;
the saved source and generated component have not been edited.

TDK recommends a minimum of 0.50 mm, not a mandatory diameter of 0.60 mm.
The PCB opening is distinct from the microphone package's own sound port.

An unconditional enlargement in the converter would incorrectly change other
parts' drill geometry. A C5656610-specific hard-coded diameter would alter
the exact supplier footprint instead of repairing its canonical library.
No converter/CLI fix PR or manually patched component was created.

EasyEDA's supported correction route is **Report Error** on the official
library. No report or email has been sent by this investigation.

## Verification and evidence

`fetch-source.ts` saves the raw response, official imported TSX and converter
Circuit JSON. `audit-import.ts` generates the board Circuit JSON and PCB /
schematic SVGs, and checks that source, TSX and rendered drill dimensions and
centers agree. The rendered footprint contains nine copper pad shapes
(five rectangular signal/power pads and four shapes for the ground terminal)
and six logical ports: WS, LR, GND, SCK, VDD, SD.

`acoustic-hole.test.ts` contains separate minimum-diameter qualification gates
for imported TSX and generated Circuit JSON. Both fail with 0.3999992 mm,
as expected. These are local investigation checks, not passing upstream
regression coverage or a completed fix.

To repeat the evidence capture and qualification checks:

```sh
bun work/microphone-import-investigation/fetch-source.ts
bun work/microphone-import-investigation/audit-import.ts
bun test work/microphone-import-investigation/acoustic-hole.test.ts
```

After the supplier library is corrected, repeat all three steps. The gates
must pass against the fresh unmodified import before qualification resumes.
Separately compare every non-hole source shape and the hole center with the
saved baseline to ensure that pads, mappings and other geometry are preserved.
